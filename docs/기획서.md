# 퍼즐 놀이터 (가칭) 기획서

- 작성일: 2026-11-14
- 버전: 0.1 (0단계 기획. 앱 코드는 아직 없음)
- 함께 볼 문서: `docs/결정사항.md`(정할 것과 추천값), `docs/조사.md`(출처, 검증 수치)

## 1. 한 줄 정의

논리 퍼즐을 한 번도 안 풀어 본 사람이 짧은 설명과 직접 풀어 보는 문제를 따라가다 보면, **9×9 스도쿠와 8×8 고양이 자리 퍼즐을 추측 없이 끝까지 풀고, 막혔을 때 다음 한 수의 이유를 스스로 찾을 수 있게 되는** 학습 웹앱.

## 2. 대상과 목표

### 대상
- 1차 대상: 사용자 본인(어른)이 배우고 즐기는 것. 초3·초6·중2 자녀도 함께 쓴다.
- 말투와 분량은 초등 3학년이 혼자 읽을 수 있는 기준(바둑 첫걸음과 같음). 어른은 단원을 건너뛰고 바로 "자유 연습"과 "오늘의 퍼즐"로 갈 수 있다.
- 난이도 폭: 4×4 스도쿠(주어진 수 8개, 마지막 빈칸만으로 풀림)부터 X-윙이 꼭 필요한 9×9까지, 4×4 고양이 자리부터 9×9 "가정해 보기"까지.
- 대상이 아닌 것: 대회 수준 기법(체인, 고급 스타 배틀 2★), 시간 경쟁, 순위표.

### 학습 목표 (완주 기준)
1. 스도쿠 규칙(가로줄·세로줄·상자)을 4×4, 6×6, 9×9에서 쓴다.
2. 마지막 빈칸, 숨은 한 자리, 하나뿐인 숫자로 쉬운 9×9를 끝까지 푼다.
3. 메모(후보 숫자)를 쓰고, 가리키기·차지하기, 짝으로 후보를 지운다.
4. 고양이 자리 규칙 네 가지(구역·가로줄·세로줄마다 하나, 닿지 않기)를 쓴다.
5. 한 줄에 갇힌 구역, 모두가 닿는 칸, 묶어서 보기로 8×8을 푼다.
6. 가정해 보기를 "추측"과 구별해 쓴다(두었다고 해 보고 모순이면 지운다).

### 성공 기준
- 한 차시 5~10분. 설명 화면 하나에 글은 세 문장 이내(바둑 첫걸음 규칙 그대로).
- 설명만 읽고 넘어가는 차시가 없다. 모든 차시에 직접 놓아 보는 활동이 있다.
- 모든 문제는 해가 하나이고, 그 차시까지 배운 기법만으로 풀린다(빌드 때 자동 검산).
- 인터넷 없이 열리고, 휴대폰 세로 화면에서 한 손으로 조작된다.

## 4. 용어와 이름 원칙

- 퍼즐 이름: "스도쿠", "고양이 자리"(가칭, 장르 이름은 스타 배틀). KenKen, Queens, Meowdoku라는 말은 앱 화면에 쓰지 않는다. 앱 안 "퍼즐 이야기" 화면에서만 "이 퍼즐은 스타 배틀이라는 장르예요"처럼 장르 이름을 밝힌다.
- 고양이 그림은 직접 그린 SVG(단순한 머리 모양 하나, 우리 색). 설정에서 별로 바꿀 수 있다.
- 기법 이름은 우리말로 짓고, 처음 나올 때 한 줄로 풀어 준다. 영어 이름은 용어 사전에만 둔다.

## 5. 학습 과정

한 차시의 흐름(바둑 첫걸음과 같음): 한 장 설명 → 따라 풀기(정해진 순서로 한 걸음씩) → 문제 3~5개 → 한 줄 정리. 단원 끝에 미션 하나.
홈에는 두 갈래 길(스도쿠 길, 고양이 자리 길)이 있고, 어느 쪽부터 해도 된다. 각 길 안에서는 앞 차시를 마쳐야 다음이 열린다.

### 5.3 차시 밖에서 하는 것
- **자유 연습**: 퍼즐, 판 크기, 난이도(기법 상한)를 골라 새 문제를 기기에서 바로 만든다.
- **오늘의 퍼즐**: 날마다 스도쿠 1개 + 고양이 자리 1개. 날짜를 씨앗으로 만들어 가족 모두 같은 문제를 받는다. 프로필마다 쉬움·보통·어려움 중 하나를 고른다.
- **퍼즐 이야기**: 스도쿠와 스타 배틀이 어디서 왔는지 한 화면씩(출처 있는 내용만).

## 6. 기능

### 6.1 1차 범위
1. **판**: 스도쿠 4×4, 6×6, 9×9 / 고양이 자리 4×4~10×10. 눌러서 칸 고르기 → 숫자 단추(스도쿠), 한 번 누르면 ×, 두 번 누르면 고양이(고양이 자리). 키보드: 화살표, 숫자, 스페이스.
2. **규칙 엔진**: 규칙 위반 찾기, 해 세기(유일해 확인), 사람 기법 풀이기(다음 한 단계와 그 이유 만들기).
3. **차시 화면**: 설명 → 따라 풀기 → 문제 → 정리. 바둑 첫걸음 차시 틀 재사용.
4. **문제 유형**
   - 채우기: 정답 숫자 놓기 / 고양이 놓기
   - 짚기: 조건에 맞는 칸 누르기(겹친 숫자, 지워지는 칸, 갇힌 구역)
   - 지우기: 이 기법으로 지울 수 있는 후보(칸)를 모두 지우기
   - 고르기: 보기 중 선택("이 칸에 들어갈 수 있는 숫자는 몇 개?")
   - 따라 풀기: 정해진 순서로 한 걸음씩
   - 한 판 풀기: 퍼즐 하나를 끝까지
5. **힌트(다음 논리 단계 설명형)**: 6.3절.
6. **메모**: 스도쿠 후보 숫자 적기, 숫자를 놓으면 같은 줄·칸·상자의 메모 자동 지우기(설정으로 끔). "메모 자동 채우기"는 4단원부터 열린다.
7. **실수 처리**: 기본은 하트 없음. 규칙 위반(같은 줄에 같은 숫자, 닿는 고양이)은 바로 표시하고 이유를 한 문장으로. 규칙은 안 어겼지만 답이 아닌 수는 "확인" 단추를 눌렀을 때나 끝났을 때 알려 준다. 어른용 "도전 모드"에서는 틀린 수를 바로 알리고 하트 3개.
8. **진행도와 기록**: 프로필 최대 5명, 기기 안 저장. 차시 별 1~3개(틀림 + 힌트 횟수), 단원 배지, 오늘의 퍼즐 달력(푼 날 표시), 퍼즐별 최고 기록 시간(내 기록만).
9. **되돌리기·다시 하기**, 진행 중인 퍼즐 자동 저장.
10. **용어 사전**: 기법 카드(작은 판 그림 + 한 줄 설명).

- 매스도쿠(2차), 노노그램(3차), 킬러 스도쿠·카쿠로·슬리더링크(검토), 2★ 스타 배틀, 종이 인쇄용 학습지, 문제 공유 링크.

### 6.3 힌트: 다음 논리 단계 설명형
풀이기가 지금 판에서 가장 쉬운 다음 단계를 찾아, 세 번에 나눠 보여 준다.

| 단계 | 보여 주는 것 | 예(고양이 자리, 실제 풀이기 출력에서) |
| --- | --- | --- |
| 1. 어디를 볼까 | 볼 곳(줄·구역)을 테두리로 표시, 한 문장 | "7번 구역을 보세요." |
| 2. 왜 그럴까 | 기법 이름과 이유 | "7번 구역의 자리가 모두 7번째 가로줄에 있어요. 그래서 그 줄의 다른 칸은 비워 둬요." |
| 3. 이렇게 해요 | 놓을 칸 또는 지울 칸을 직접 표시 | 지울 칸에 × 미리 보기 |

- 이유 문장은 기법마다 틀을 두고 칸·구역 이름을 끼워 만든다(검증 스크립트에서 이미 만들어 봄).
- 메모가 틀려서 다음 단계가 안 보일 때(스도쿠): "메모 중에 지워야 할 것이 남아 있어요"처럼 메모 문제를 먼저 알려 준다.
- 사용자가 둔 수가 답과 다르면 힌트는 그 수를 먼저 짚는다("이 칸은 다시 보세요").
- 힌트를 쓰면 별이 줄지만 횟수 제한은 없다.

### 6.4 아이 친화 원칙 (바둑 첫걸음과 같음)
- 터치 영역 44px 이상. 9×9 스도쿠는 휴대폰 세로(390px 폭 기준 계산)에서 한 칸이 40px에 못 미치므로, 숫자 입력은 칸 직접 입력이 아니라 "칸 고르기 → 아래 숫자 단추"로 한다.
- 틀려도 벌점이 없다(기본 모드). 이유를 알려 주고 바로 다시.
- 구역은 색만으로 구별하지 않는다: 색 + 굵은 경계선 + (설정) 무늬.
- 시간 제한, 순위표는 없다. 시간 기록은 끄고 켤 수 있다.

## 7. 문제 생성, 난이도, 유일해 보장

### 7.1 방식: 미리 만든 묶음 + 기기에서 생성 (섞기)

| 쓰는 곳 | 방식 | 이유 |
| --- | --- | --- |
| 차시 문제, 따라 풀기, 단원 미션 | 빌드 때 스크립트로 만들어 자료 파일에 넣는다. 빌드 검사기가 유일해·기법 상한·기법이 꼭 필요한지를 다시 확인한다 | 설명 문장과 문제가 정확히 맞아야 함. 드물게 나오는 문제(X-윙이 꼭 필요한 9×9는 400개 중 3개)는 미리 골라야 함 |
| 오늘의 퍼즐 | 기기에서 날짜 씨앗으로 생성 | 서버 없이 가족 모두 같은 문제. 7×7 두 번 생성해 같은 판이 나오는 것을 확인함. 생성기 판 번호를 기록에 남긴다 |
| 자유 연습 | 기기에서 생성. 스도쿠 전 크기, 고양이 자리 8×8까지. 9×9·10×10 고양이 자리는 미리 만든 묶음에서 | PC 측정으로 고양이 자리 9×9(고른 구역)는 95%가 0.65초, 최대 1.2초, 10×10은 최대 9초라 휴대폰에서 기다림이 길 수 있음 |

### 7.2 스도쿠
- 생성: 무작위 완성판 → 칸을 무작위 순서로 지우며 해 세기(해 2개에서 멈춤)로 유일해 확인. 단계 맞춤은 지울 때마다 "정한 기법까지만으로 풀리는가"도 확인한다.
- 난이도: 사람 기법 풀이기가 쉬운 기법부터 적용했을 때 쓴 가장 어려운 기법. 같은 기법 안에서는 단계 수와 주어진 수로 쉬움·보통을 나눈다(값은 M1에서 정함).
- 측정(PC, `docs/조사.md` 5.1): 9×9 생성 중앙 2.59ms·95% 9.38ms, 400/400 유일해. 4×4 "마지막 빈칸만" 문제는 주어진 수 8개로 100% 나옴.
- 대칭(주어진 수 배치를 대칭으로)은 넣지 않는다(보기 좋지만 생성이 느려짐, 필요하면 M3에서 검토).

### 7.3 고양이 자리
- 생성: 고양이 자리를 먼저 정함 → 고양이 칸마다 구역 씨앗 → 이웃 칸을 붙여 구역을 키우며 매번 해를 2개까지 셈 → 해가 둘이 되는 붙이기는 버림 → 막히면 처음부터. 구역이 고르게 되도록 "작은 구역부터 키우기"를 기본으로 하고(가장 작은 구역 중앙 3칸), 첫 단원 문제는 "그냥 키우기"(한 칸·두 칸 구역이 많아 쉬움)에서 고른다.
- 난이도: 다섯 기법(마지막 자리 → 한 줄에 갇힌 구역 → 모두가 닿는 칸 → 묶어서 보기 → 가정해 보기)으로 판정. 측정한 1,300개 판 모두 다섯 기법으로 풀렸다.
- 측정(PC, `docs/조사.md` 5.2): 8×8 그냥 키우기 중앙 1.40ms, 고른 구역 중앙 18ms·95% 86ms. 모든 크기 실패 0, 유일해 100%.

### 7.4 빌드 검사기가 막는 것
- 해가 하나가 아닌 문제, 차시 기법 상한을 넘는 문제, "이 기법이 꼭 필요한" 차시인데 더 쉬운 기법으로 풀리는 문제.
- 설명 문장 세 문장 초과, 힌트 문장 틀에 빈 이름.
- 같은 문제가 두 번 나옴(뒤집기·돌리기·숫자 바꾸기로 같아지는 것 포함).

## 9. 데이터 구조

차시 자료는 코드와 분리해 `src/lessons/`에 둔다. 판은 글자 그림으로 적는다(바둑 첫걸음 방식).

스도쿠 판 글자: `.` 빈칸, `1`~`9` 주어진 수, `*` 이 걸음의 정답 칸, `?` 질문 칸.

```js
{
  type: 'fill', tech: 'hidden-single', size: 4,
  text: '왼쪽 위 상자에 3이 들어갈 곳은 한 곳뿐이에요.',
  right: '맞아요. 다른 칸은 같은 줄에 이미 3이 있어요.',
  wrong: '아쉬워요. 그 칸의 가로줄과 세로줄을 보세요.',
  board: ['...3', '.*..', '3...', '....'],
  answer: 3,
}
```

(모양 예시. 왼쪽 위 상자의 네 칸 중 첫 세로줄 두 칸은 아래의 3 때문에, 첫 가로줄 칸은 오른쪽 위의 3 때문에 안 되고 `*` 칸만 남는다. 이 한 걸음만 본 것이고 판 전체의 유일해는 묶음에 넣을 때 검사기가 확인한다.)

고양이 자리 판 글자: 대문자 `A`~`J` 구역, `*` 정답 고양이(자료에서만, 화면에는 안 보임), `x` 미리 지운 칸.

```js
{
  type: 'solve', tech: 'one-line', size: 5,
  text: 'A 구역은 맨 위 줄에만 있어요. 그 줄의 다른 칸을 지워 보세요.',
  regions: ['AABBB', 'CCCBB', 'CDDEE', 'DDDEE', 'DDEEE'],
}
```

(검증 스크립트로 확인: 해 1개, 가장 어려운 기법은 한 줄에 갇힌 구역. 풀이기의 첫 힌트 문장은 "1번 구역의 자리가 모두 1번째 가로줄에 있어요. 그래서 그 줄의 다른 칸은 비워 둬요.")

- 정답은 자료에 적지 않아도 된다. 빌드와 시험에서 엔진이 풀어 확인한다(적어 두면 엔진 답과 같은지 비교).
- 미리 만든 문제 묶음: `src/packs/<퍼즐>-<크기>-<기법>.mjs`에 한 줄 문자열 배열. 9×9 스도쿠 한 문제 81글자, 9×9 고양이 자리 81글자. 묶음 전체 목표 100KB 이하.
- 진행도 저장(localStorage `puzzle-guide:v1`):

```json
{ "version": 1, "current": "p1", "profiles": [ {
  "id": "p1", "name": "이름", "color": 0,
  "done": { "S03": { "stars": 3 }, "C02": { "stars": 2 } },
  "missions": { "S-u1": true },
  "daily": { "2026-11-14": { "sudoku": 312, "cats": 205, "gen": 1 } },
  "best": { "sudoku-9-easy": 420 },
  "inProgress": null,
  "review": [], "last": "S03"
} ] }
```

`daily`의 숫자는 걸린 초, `gen`은 생성기 판 번호(생성기를 고치면 올림).

## 10. 기술 구성 (바둑 첫걸음 구조 재사용)

- **한 파일 웹앱**: `index.html` 하나에 화면, 스타일, 스크립트, 자료. 외부 글꼴·라이브러리·서버 요청 없음. 파일로 열어도 동작.
- **개발 구조**: `src/`에 ES 모듈로 나눠 쓰고 `node build.mjs`로 합친다(바둑 첫걸음 `build.mjs`를 가져와 고침).
  - `src/sudoku/{rules,solve,grade,generate}.mjs`, `src/cats/{rules,solve,grade,generate}.mjs` (화면과 무관한 순수 함수, 이번 검증 스크립트를 다듬어 옮김)
  - `src/rng.mjs` 씨앗 난수, `src/hint.mjs` 힌트 문장 틀
  - `src/lessons/sudoku-u1~u5.mjs`, `src/lessons/cats-u1~u5.mjs`, `src/packs/*.mjs`, `src/glossary.mjs`
  - `src/store.mjs`, `src/settings.mjs` (바둑 첫걸음 것을 가져와 고침: 프로필 5명, 기록 내보내기·가져오기, 밝은·어두운 화면)
  - `src/ui/board-sudoku.js`, `src/ui/board-cats.js`(SVG), `src/ui/app.js`, `src/style.css`, `src/index.template.html`, `src/sw.template.js`
  - `tools/make-packs.mjs` 문제 묶음 만들기, `tools/feasibility/` 이번 검증 스크립트
- **저장**: localStorage. 막힌 환경에서도 동작(저장만 안 됨).
- **인터넷 없이 열기**: 주소(https)로 열면 서비스 워커(바둑 첫걸음 v1.1 방식).
- **생성 시간이 긴 경우**: 기기 생성은 0.5초를 넘으면 "만드는 중" 표시. 필요하면 Web Worker(한 파일 안의 Blob 스크립트)로 옮긴다(M3에서 휴대폰 측정 후 결정).
